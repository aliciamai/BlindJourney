Auth
POST /api/auth/registro Crear cuenta nueva

Sin auth. Crea la cuenta y envía email de verificación.
Respuesta 201: { message, usuarioId } · 409 si el email ya existe.

POST /api/auth/login Login → guarda token automáticamente

Sin auth. Devuelve { token, refreshToken, usuario }.
El token JWT se guarda automáticamente en la barra superior y en localStorage.
El email debe estar verificado (403 EMAIL_NOT_VERIFIED si no).

POST /api/auth/logout Cerrar sesión (invalida refresh token)

Sin auth. Elimina el refresh token de la BD. El JWT de acceso caduca solo (stateless).
Body: { refreshToken? } — se rellena automáticamente tras el login.

GET /api/auth/verificar/:token Activar cuenta por email

Sin auth. Activa la cuenta y redirige al frontend.
El :token llega en el email de verificación (64 chars hex).

POST /api/auth/recuperar-password Solicitar email de recuperación

Sin auth. Genera token de reset (1 h) y manda email.
Devuelve siempre 200 con el mismo mensaje (para no revelar qué emails existen).

POST /api/auth/nueva-password Cambiar contraseña con token del email

Sin auth. Usa el token del email de recuperación (caduca en 1 h).
Body: { token, nuevaPassword }.

POST /api/auth/refresh Renovar JWT → guarda nuevo token

Sin auth. Intercambia el refresh token por un nuevo JWT de acceso.
Body: { refreshToken } — se autocompleta tras el login.

Viajes 🔒 requiere token
GET /api/viajes Listar todos los viajes del usuario

Devuelve { items: [], message }. Filtra automáticamente por el usuario del JWT.

GET /api/viajes/:id Obtener un viaje por ID

Devuelve el detalle de un viaje. 404 si no pertenece al usuario.

POST /api/viajes Crear viaje sorpresa

Body: { destino, presupuesto?, fechaInicio?, duracion? }.
El destino es interno; el usuario no lo ve hasta la revelación.

PATCH /api/viajes/:id/revelar Revelar el destino sorpresa

Cambia el estado del viaje a «revelado» y devuelve el destino real.
Body vacío {}. Requiere que pasen las 48 h configuradas o que se fuerce manualmente.

Reservas 🔒 requiere token
GET /api/reservas Listar reservas del usuario

Devuelve { items: [], message } con todas las reservas activas del usuario.

POST /api/reservas Crear reserva ligada a un viaje

Body: { viajeId, hotel, noches, tipo?, precio? }.
El viaje debe pertenecer al usuario autenticado.

PATCH /api/reservas/:id/cancelar Cancelar una reserva

Cambia el estado de la reserva a «cancelada». Body vacío {}.
404 si la reserva no existe o no pertenece al usuario.

Itinerarios 🔒 requiere token
GET /api/itinerarios/viaje/:viajeId Obtener itinerario de un viaje

Devuelve el itinerario generado (días, actividades, horarios).
404 si el viaje no tiene itinerario o no pertenece al usuario.

POST /api/itinerarios/viaje/:viajeId/regenerar Regenerar itinerario con IA

Descarta el itinerario actual y genera uno nuevo con Gemini AI.
Body vacío {}. Puede tardar varios segundos.

Perfil 🔒 requiere token
GET /api/perfil/me Obtener perfil del usuario autenticado

Lee el usuario directamente del JWT. No consulta la BD.
Devuelve { usuario: { id, email, nombre }, message }.

PUT /api/perfil/me Actualizar datos del perfil

Body: { nombre?, apellidos?, telefono?, idioma? }. Solo se actualizan los campos enviados.
Devuelve { message, cambios } con lo que se ha guardado.

Notificaciones 🔒 requiere token

Query params: pagina (def. 1), limite (def. 20, max 50), solo_no_leidas (true/false).
Devuelve { items, total, pagina, paginas }.

PATCH /api/notificaciones/leer-todas Marcar todas las notificaciones como leídas

Body vacío {}. Devuelve { message: "N notificaciones marcadas como leídas" }.

PATCH /api/notificaciones/:id/leer Marcar una notificación como leída

Body vacío {}. 404 si la notificación no existe o no pertenece al usuario.

DELETE /api/notificaciones/:id Eliminar una notificación

Elimina permanentemente la notificación. 404 si no existe o no pertenece al usuario.

Casos de Error — peticiones preconfiguradas para provocar cada respuesta de error del backend
🔑 JWT / Autorización
GET /api/viajes Sin Authorization header → 401 NO_TOKEN

Envía la petición sin token. El middleware JWT responde con { error: "Acceso no autorizado. Token requerido.", code: "NO_TOKEN" }.

GET /api/viajes Token con firma inválida / manipulado → 401 INVALID_TOKEN

Envía Authorization: Bearer token.invalido.firma_falsa. El middleware responde con { error: "Token invalido.", code: "INVALID_TOKEN" }.

GET /api/viajes Token expirado (pega uno antiguo) → 401 TOKEN_EXPIRED

Necesitas un JWT real de una sesión anterior ya caducada (los tokens duran 1 h). Pégalo aquí — no modifica el token activo de la barra superior.
Respuesta esperada: { error: "Token expirado. Por favor, renueva tu sesion.", code: "TOKEN_EXPIRED" }.

📋 Auth — Validaciones (400)
POST /api/auth/registro Cuerpo vacío — todos los campos ausentes → 400

Envía {}. El validador rechaza con los errores: nombre, apellidos, email y password requeridos.

POST /api/auth/registro Email con formato inválido → 400

Envía email: "no-es-un-email". Respuesta: { error: "Datos de entrada no validos", detalles: [{ campo: "email", mensaje: "Debes indicar un email valido" }] }.

POST /api/auth/registro Password demasiado corta (menos de 8 chars) → 400

Envía password: "abc". Respuesta: { error: "Datos de entrada no validos", detalles: [{ campo: "password", mensaje: "La password debe tener al menos 8 caracteres" }] }.

POST /api/auth/login Email con formato inválido → 400

Envía email: "no-es-email". El validador rechaza antes de consultar la BD.

POST /api/auth/login Sin campo password → 400

Envía solo { email: "test@example.com" }. El validador rechaza por password ausente.

GET /api/auth/verificar/:token Token de verificación inválido o ya usado → 400

Usa un token hex de 64 chars inventado. Respuesta: { error: "Token de verificación inválido o ya utilizado" }.

POST /api/auth/nueva-password Token de reset inválido o expirado → 400

Envía un token de reset falso. Respuesta: { error: "Token inválido o expirado. Solicita un nuevo enlace." }.

🚫 Auth — Credenciales (401 / 403)
POST /api/auth/login Credenciales incorrectas (usuario inexistente) → 401

Email que no existe en la BD. Respuesta: { error: "Credenciales incorrectas" }. El backend usa el mismo mensaje para email inexistente y password errónea (anti-enumeración).

POST /api/auth/login Email registrado pero sin verificar → 403 EMAIL_NOT_VERIFIED

Registra un usuario pero no hagas clic en el link del email, luego intenta hacer login. Respuesta: { error: "Debes verificar tu email antes de iniciar sesión", code: "EMAIL_NOT_VERIFIED" }.

🔄 Auth — Refresh Token (401)
POST /api/auth/refresh Sin refresh token en el body → 401

Envía {}. Respuesta: { error: "Refresh token requerido" }.

POST /api/auth/refresh Refresh token con firma inválida → 401

Envía un refresh token con estructura JWT pero firma incorrecta. Respuesta: { error: "Refresh token inválido" }.

POST /api/auth/refresh Refresh token válido pero ya revocado (sesión cerrada) → 401

Haz login, copia el refresh token, haz logout y pégalo aquí. Respuesta: { error: "Refresh token revocado" }.

⚠️ Conflictos de Estado (409)
POST /api/auth/registro Email ya registrado → 409

Intenta registrar un email que ya existe en la BD. Respuesta: { error: "Este email ya está registrado" }.

PATCH /api/viajes/:id/revelar Destino ya revelado anteriormente → 409

Intenta revelar un viaje cuyo destino ya está revelado. Respuesta: { error: "El destino ya fue revelado" }.

PATCH /api/reservas/:id/cancelar Reserva ya cancelada anteriormente → 409

Intenta cancelar una reserva que ya está cancelada. Respuesta: { error: "La reserva ya está cancelada" }.

POST /api/itinerarios/viaje/:viajeId/regenerar Destino no revelado aún — no se puede regenerar → 409

Regenerar el itinerario requiere que el destino esté revelado. Respuesta: { error: "El destino aún no ha sido revelado" }.

🔍 Recursos No Encontrados (404)
GET /api/viajes/99999 Viaje inexistente → 404

Pide el viaje con ID 99999 (no existe o no es tuyo). Respuesta: { error: "Viaje no encontrado" }.

POST /api/reservas Crear reserva con viajeId inexistente → 404

Intenta crear una reserva ligada al viaje 99999. Respuesta: { error: "Viaje no encontrado" }.

PATCH /api/reservas/99999/cancelar Reserva inexistente → 404

Intenta cancelar la reserva 99999. Respuesta: { error: "Reserva no encontrada" }.

GET /api/itinerarios/viaje/:viajeId Viaje inexistente o sin itinerario generado → 404

Con ID 99999 → { error: "Viaje no encontrado" }. Con un viaje real sin itinerario → { error: "Este viaje aún no tiene itinerario generado" }. Cambia el ID para probar el segundo caso.

PATCH /api/notificaciones/99999/leer Notificación inexistente → 404

Intenta marcar como leída la notificación 99999. Respuesta: { error: "Notificación no encontrada" }.

DELETE /api/notificaciones/99999 Notificación inexistente → 404

Intenta eliminar la notificación 99999. Respuesta: { error: "Notificación no encontrada" }.

GET /api/documentos/viaje/99999 Documentos de viaje inexistente → 404

Pide los documentos del viaje 99999 (no existe o no es tuyo). Respuesta: { error: "Viaje no encontrado" }.

PUT /api/documentos/99999 Actualizar documento inexistente → 404

Intenta actualizar el documento 99999 (no existe, está inactivo o no es tuyo). Respuesta: { error: "Documento no encontrado" }.

DELETE /api/documentos/99999 Eliminar documento inexistente (soft delete) → 404

Intenta eliminar (soft delete) el documento 99999. Respuesta: { error: "Documento no encontrado" }.

GET /api/perfil/me Usuario del JWT no encontrado en BD (cuenta eliminada) → 404

Caso extremo: el JWT es válido pero el usuario fue eliminado de la BD. Usa un JWT de un usuario ya borrado. No modifica el token activo de la barra.
Respuesta: { error: "Usuario no encontrado" }.
